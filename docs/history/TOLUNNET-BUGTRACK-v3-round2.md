| **TNET-078** | `src/task/main.c` `tn_apply_live_config()` + `src/common/prefs.c` `tn_prefs_default()` | DNS1 default is the slirp address `10.0.2.3` and `tn_apply_live_config` unconditionally calls `dns_setserver(0, …)`. | **TNET-079** | `src/cmds/TolunnetPrefs.c` `update_daemon_button()` | `SetGadgetAttrs(gad, win, NULL, GA_Text, …)` on a GadTools `BUTTON_KIND`. Two errors: GadTools gadgets must be driven through `GT_SetGadgetAttrs()`, and OS 3.x BUTTON_KIND does **not** support changing its label after creation (`GA_Text` is not honoured by `frbuttonclass` with an IntuiText label). Result: the button never relabels; it is not build-verifiable, only visually. | Either (a) two buttons `Start` and `Stop` with `GA_Disabled` toggled via `GT_SetGadgetAttrs`, or (b) remove/recreate the gadget (`RemoveGList` / `CreateGadget` / `AddGList` / `RefreshGList`). (a) is simpler and standard. Also convert every other future `SetGadgetAttrs` on GadTools gadgets to `GT_SetGadgetAttrs`. |
| **TNET-080** | `TolunnetPrefs.c` `daemon_start()` → `Execute("Run >NIL: C:tolunnet")`; `Install_Tolunnet`; `ci/User-Startup*`; `main.c` | Daemon stack. `Execute()`/`Run` give the child the **default 4096-byte** CLI stack; from Workbench there is no CLI at all so the shell default applies. lwIP `tcp_input` → `tcp_receive` → app callback → `tn_logf`/`RawDoFmt` plus DHCP/DNS state machines exceed 4 KB. Works by luck under WinUAE JIT, Gurus on iron. No `pr_StackSize` check exists (audit 2.4 still TBD). | In `main()`: read `((struct Process*)FindTask(NULL))->pr_StackSize`; if `< 32768` either `StackSwap()` onto an `AllocMem`'d 32 KB stack for the whole run, or print "tolunnet: needs a 32 KB stack — use `Stack 32768` / the installer's User-Startup line" and exit 20. Prefs must launch with `Execute("Stack 32768\nRun >NIL: C:tolunnet")` (or `SystemTags(... NP_StackSize, 32768 ...)` — preferred: `SystemTags(cmd, SYS_Asynch, TRUE, SYS_Input, NULL, SYS_Output, NULL, NP_StackSize, 32768, TAG_END)`). Installer's User-Startup snippet: `Run >NIL: C:tolunnet` preceded by `Stack 32768`. |
| **TNET-081** | `TolunnetPrefs.c` `daemon_start()/daemon_stop()` | `Delay(5)` polling loops (up to 3 s) block the Intuition message loop; the window cannot refresh and the close gadget is dead meanwhile. | Poll from the main loop with a `timer.device` request in the `Wait()` mask (this is also what §4.2's live status line needs), or at minimum keep the loop but ≤ 1 s and `GT_RefreshWindow` in between. |
| **TNET-082** | `TolunnetPrefs.c` `notify_daemon_reconfig()` | `TnIpcMsg` on the **stack** is handed to another task via `PutMsg`. On a 68000 without MMU it happens to work, but Exec messages must live in `MEMF_PUBLIC` memory (`AllocMem(sizeof, MEMF_PUBLIC|MEMF_CLEAR)`); stack memory is not guaranteed public under a VMM/MMU setup (Enforcer/MuForce flags it). Same for any future one-shot IPC from CLI tools. | Allocate the message with `AllocMem(MEMF_PUBLIC)`; factor a `tn_ipc_oneshot(cmd, …)` helper into `src/common/` and reuse it from `TolunnetStatus`, Prefs and the future `tolunnet STATUS/STOP/RECONFIG` CLI. |
| **TNET-083** | `src/common/prefs.c` `tn_prefs_load()` precedence | Precedence is `ENV:` → `DEVS:tolunnet.config` → legacy → `ENVARC:`. After a **Save**, `ENV:` holds the same data, fine. But `DEVS:tolunnet.config` was defined as the *single source of truth* for the ART integration (§5.2) and for hand-editing: a user who edits `DEVS:` by hand and restarts the stack is silently overridden by a stale `ENV:` blob until reboot/`Use`. Also the binary blob format is version-less (“size-tolerant reader”) — one more field and old blobs mis-parse. | Decide and document one rule: recommended `DEVS:` text is canonical and `ENV:` only overrides when its **mtime is newer** than `DEVS:` (compare `ExamineFH`/`fib_Date`), or drop the blob entirely and write `ENV:tolunnet.config` as **text** too (same parser, no version problem). Add a `VERSION=` line either way. Host-test the round trip (TNET-073). |
| **TNET-077** (already logged, still OPEN) | `main.c` `tn_handle_ipc` | No handlers for `BIND / LISTEN / ACCEPT / SHUTDOWN / GETSOCKNAME / GETPEERNAME / GETHOSTBYADDR`. Consequence is wider than "servers": **every UDP client that calls `bind()` before `recvfrom()`** (NTP, DNS resolvers, TFTP, most ping/traceroute ports, AmiTCP-era tools) gets `ENOSYS`; `getsockname()` after `connect()` is used by FTP active mode and IRC clients; `shutdown(SHUT_WR)` is used by HTTP/1.0 clients and AmiSSL. This is the top compatibility blocker — it outranks every §5 feature. | Implement all seven in the daemon: `udp_bind/tcp_bind` (respect `SO_REUSEADDR`, `INADDR_ANY`, port 0 = ephemeral), `tcp_listen_with_backlog` + `tcp_accept` callback into a per-listener accept queue (bounded, `TN_MAX_RX_QUEUE_PER_SOCKET` style) with blocking/non-blocking `accept` and `WaitSelect` readability, `tcp_shutdown(pcb, rx, tx)`, local/remote address fill from the pcb (`sin_len=16`, `sin_family=AF_INET`), `gethostbyaddr` via reverse DNS. Add `TestSocket` cases: UDP bind+recvfrom, TCP listen+accept loopback (needs loopback, TNET-071), FTP-style `getsockname`. |
